# Live application audit · October 16, 2026

This pass inspected the running `https://deploy.local` application at 1280 × 800 and 390 × 844. The local fixture was used for populated repository, conversation, issue, pull-request and review states because the live workspace has no projects or tasks. Captures are observations of specific states, not proof that every production operation was executed. System dark appearance was visually inspected; light tokens were reviewed in source.

Release `683e049adb593ca477940a8fb6de6ca527600127` is active on SER. Activation and trusted HTTPS readiness passed without a sudo prompt. The final live checks confirmed the two current catalog computers, fixed switch geometry, design-reference fragment restoration and working computer navigation. Forma reported running with a healthy service after the final restart. The evidence index contains 98 observations, including loading and fixture states; final captures also include the restored default browser size.

## Verification and operational limits

Scoped formatting and lint, TypeScript checking and production builds passed. SER prepares clean release checkouts from the pushed feature branch, excluding unrelated existing local changes. Each prepared candidate ran 573 server tests: 559 passed, 14 skipped, no failures. These server tests do not verify browser appearance. The installed `deploy-update` activated the main fixes over SSH as the normal user without sudo authentication; final release identity and readiness are recorded in `ser-verification.json`.

This is not an end-to-end execution sign-off. Live SER reports its task computer offline and has no tasks/projects, so coding execution and populated workspace views could not be exercised there. Populated UI checks used the existing isolated fixture, not production test data. Multi-file/nested-directory fixtures, physical native devices, other browser engines and light-mode screenshots were not part of this pass.

Separate runtime issues were observed: the repository supervisor repeatedly reports that its worker already has an owner, and Forma's application status briefly reported unknown after the control-plane restart while inventory still reported a healthy remote container. Another Forma deployment was in progress during the final checks. Existing worker processes, leases, live deployments and the user's pending server/native changes were left alone. These observations prevent a claim that every backend workflow is healthy.
