## Captures and deliberate differences

- `Home-1440.png`, `Home-700.png`: same sidebar fixtures, greeting, composer, starters, proportions and responsive breakpoint as Home. The small “Design preview · sample data” caption distinguishes the static shell from live health/account data. Search, panel, attach, model, voice and send are disabled until their slices supply behavior, so their icons are lighter than the board. Starter links open the Scout skeleton; task, inbox and account links open their registered routes. The sidebar uses an accessible aside with a navigation landmark, and the compact menu opens a modal drawer. The account settings icon has no extra invisible button wrapper.
- `DesignSystem-1440.png`, `DesignSystem-700.png`: same content, colors, component hierarchy and examples as DesignSystem. At 700 the reference board is a clipped 1440-wide sheet; the implementation deliberately stacks sections, uses 32 px insets and a 30 px reference headline, and exposes the entire page. It preserves 22 px application titles. The type table uses a consistent row inset; the headline and description have slightly different vertical spacing. Native buttons and controls retain their real interaction states. The expanded work log uses a down chevron, correcting the board's right chevron on expanded content. Running work animates unless reduced motion is requested. The composer explanation uses typographic quotation marks. The switch/shape examples use border-box sizing. These are deliberate improvements over the fixed reference markup; the design source remains untouched as required by this task.
- `States-1440.png`, `States-700.png`: same empty, loading, warning, failure and invalid-field examples as States. The narrow sheet reflows instead of clipping, and its capture includes the entire page. The reference's slow-connection notice is an explicit specimen; the reusable Skeleton separately displays its supplied slow message after 10 seconds, without duplicating the specimen notice. The field error stays associated with its native input. Error examples use live status/alert semantics. A work log without steps has no empty disclosure control.
- `captures/Components-dark-1440.png`, `captures/Components-dark-700.png`: additional dark-theme specimens for the families not on the two overview boards. The matrix is a table at 1440 and one group per agent at 700; every action defaults to Ask me. There is no corresponding dark overview board to pair. The reference page offers Light/Dark and Default/Hover/Focus-visible/Disabled/Loading controls for all specimens. Passive text/layout families use their interactive descendants' hover/focus behavior; disabled/loading containers are inert and marked with their state, while buttons and fields use native disabled semantics. Dialogs use the browser's modal focus handling and can be inspected in each state through the always-available example trigger.
- The normal reference page combines Foundations, States and Every component and adds a review toolbar. Capture-only query parameters select one board and hide that toolbar. Additional examples, theme controls, focus previews and the answered decision record extend the reference boards without changing their content hierarchy.
- Other routes intentionally contain only a board-shaped header, the shared sidebar and “This screen is coming.” Resource headers use their URL identity; project sections retain the project header, task sections retain the task header, and Settings subpages retain the Settings header. Header actions that need later slices are disabled. No real project, release, task, app, computer or settings screen is implemented here.

Chrome DevTools captured at exactly 1440/700 CSS px with device scale 2; source images were normalized to CSS pixels before pairing. Home is 900 px high; the desktop reference boards are 1360 and 720 px high. Narrow reference captures use full document height. These were inspected visually after pairing. No design/v2 files were changed.

## Remaining integration and next slice

**HTTP 308 is not connected to the host.** `react-flight-router` 0.12's production SSR handler follows a server-component redirect and renders its destination with HTTP 200; the dev renderer treats the redirect error as a route error. Using its `redirect()` API therefore cannot satisfy the brief. All registered old routes now work through client redirects. `app/routes/dashboard/v2-redirects.ts` exports the tested `permanentRedirectResponse(request, projectForApplication)` adapter, which returns a real HTTP 308 with Location. The server owner must invoke it before the host's RSC/SSR handler; editing that handler is outside this slice's explicit scope. For requests with only browser-local credentials, keep the client lookup fallback.

The brief names `/api/application-repositories?application=`; this checkout mounts the resource at `/api/workspace/application-repositories?application=`. The resolver first tries the brief's path, then the existing path on 404, using the current session headers. A missing project or unavailable lookup falls back to Live. Identity `/dashboard/projects` stays put, avoiding a redirect loop. New docs URLs temporarily render the existing docs modules; their rewrite belongs to slice 11.

Import the new primitives from `@/components/ui`; existing exports are preserved. `Action`, `Field` and `Switch` are the v2 controls alongside legacy `Button`, `TextField` and `Toggle`. New components accept disabled/loading state, and collection controls take data and callbacks rather than fetching. Replace `V2Sidebar`'s fixture data and the shared placeholder route modules as the real slices land. The new shell deliberately replaces the old dashboard route layout without editing it, root.client, the legacy sidebars, global styles, shared contracts or server code.
