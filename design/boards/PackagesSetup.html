On deploy.local’s computers

Tasks, pipelines and releasesInstall through deploy.local with each computer’s own key. Nothing to set up.On

A project can turn this off in its settings, under Packages.

Publish from a pipeline

Once every job passes on main, the pipeline publishes each listed package whose version is new.
# deploy.yaml
pipeline:
  on: [push]
  branches: [main]
  jobs:
    test:
      run: pnpm test
      runsOn: { os: linux }
  publish:
    - packages/react-flight-router

Change the version in a pull request and merging publishes it. Any other run skips it, because that version is already published. Pull requests never publish.

In a project

Install from deploy.localWrites these two files. Commit them and everyone who clones the project installs from here.deploy packages use
# .npmrc
registry=https://deploy.local/npm/

# .cargo/config.toml
[registries.deploy-local]
index = "sparse+https://deploy.local/cargo/index/"

[source.crates-io]
replace-with = "deploy-local-crates-io"

[source.deploy-local-crates-io]
registry = "sparse+https://deploy.local/cargo/crates-io/"

Once they’re committed, anyone who can’t reach deploy.local can’t install the project, including you when you’re away from SER. deploy packages use --off removes them. Neither file holds a key.
