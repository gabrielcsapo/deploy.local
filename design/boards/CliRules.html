CLI · design rules

The same product, in a terminal.

The CLI follows the app's vocabulary, status rules and palette (the dark theme's tokens). Six rules keep it from drifting again.
01The app's wordsProjects, apps, Live, computers, tasks, Waiting on you. Never graph, component, site or suitcase outside deploy help advanced.
02[app] is positionalIt defaults to the project in this folder. -a still works so old scripts keep running.
03Steps, not logsOne line per step with ✓ ✗ ⠋. Raw output stays in deploy logs; failures show only the lines that explain them.
04End with the next commandEvery run ends with what happened and what to run next: an address, deploy logs, deploy inbox.
05Ask before changing dataRollbacks, removals and migrations list exactly what changes and ask [y/N]. --yes is for scripts.
06Scriptable--json on every command, no color when piped or with NO_COLOR. Exit 0 ok, 1 failed, 2 usage, 3 waiting on you.
