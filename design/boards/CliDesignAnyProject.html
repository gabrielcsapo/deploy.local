CLI · design

Start a design in any project.

deploy design was written for deploy.local's own repository: an HTTPS origin, a design already drawn, a main that origin has. Now the project is read from an SSH origin or given by name, and checked before anything is made. start says when main here is ahead of origin. A project with no design gets its first canvas, a board and a README that says how they are written, so there is no command to learn the format from.

To draw from your newer main:
  git push origin main
  git -C ../catan-harbor-trade merge origin/main

This project had no design. How one is written:
  design/README.md

Edit the boards in design/boards. To see them as you save:
  cd ../catan-harbor-trade
  deploy design dev

~/catan $ deploy design start "Harbor trade" --project catam

design/README.mdstart writes it with the first canvas and board
zsh
~/catan-harbor-trade $ cat design/README.md
# Design

This folder is the app's design: one board per screen, reviewed
on deploy.local's Design page before anything is built.

## canvas.json
{ "title", "boards": { "<Name>.html": { "x", "y", "w", "h", "title" } },
  "order": ["<Name>.html"], "notes": { "<id>": { "x", "y", "text" } } }
Web boards are 1440 wide and are checked at 700 too. Phone boards
are 390. Place boards apart on the canvas.

## boards/<Name>.html
One standalone page per board, sized by
<meta name="design-board" content="width=1440,height=900">
No scripts and no remote images. Pictures sit beside the boards,
in boards/captures: deploy design capture puts the running app there.
Every element someone might point at carries a data-layer ID,
unique in its board. deploy design check adds them. Keep them.

## Style
The board's own <style>, or design/ds if this project has one.

## Changing the design
deploy design start "<title>", then deploy design dev to see
the boards on the Design page as you save. deploy design propose
asks for review, and deploy design feedback --wait hears back.
