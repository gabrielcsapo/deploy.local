Releases and rollback

A release is one version of a whole project: every app in it, plus its database migrations. You start every release, by pressing Ship or merging a pull request.

How a release runs

  • Prepare · build every app in the project
  • Verify · start the release on a copy and check that it answers
  • Activate · switch traffic and run migrations
  • Watch · deploy.local checks health for 10 minutes

If verify fails, nothing changes; the project stays on the release it had. You can follow each step in the project's Releases, on iPhone, or with deploy releases.

Rolling back

Rollback moves the whole project back to an earlier release, so its apps never run different versions. Migrations made since are undone when they can be.

When a migration can't be undone, rollback restores the backup taken just before that release, and tells you what data from after it would be lost before you confirm.

When Ops watcher rolls back by itself

An owner-created agent such as Ops watcher asks first. Confirm its monitoring routine before it runs. You can let it roll back on its own in Approvals, per project, for a release in its first 10 minutes.

From the CLI

~/code/home-gym deploy releases
  81be0d2  Oct 25  PR #42  web app, sync worker      previous
  9c3e1fa  Today   PR #43  web app, sync worker, 0042 live · failing

~/code/home-gym deploy rollback
Roll back home-gym to 81be0d2? Both apps move and migration 0042 is undone. [y/N]
