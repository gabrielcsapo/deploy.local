One server plan

deploy.local · not on main yet

deploy.local runs as one server process. Background timers start from the server’s boot code, and the event service and the record store live in the kernel.

What moves

  • The event service and the record store move into the kernel. The old paths stay as re-exports for one release.
  • Timers start when the server boots, not when a file is imported.
  • A worker removes a job’s checkout when the job finishes.

Order of work

Each step ships on its own and leaves the server working. Nothing here changes what people see.
