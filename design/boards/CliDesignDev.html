CLI · design

See it as review will, while you draw.

A change needs start, propose and feedback. While you draw, deploy design dev serves the Design page itself from the terminal, on this folder: the same canvas as deploy.local, with nothing uploaded, following each save (DesignLocal.html). check and propose are drawn by deploy.local, as review draws them, so no project keeps a check script and the terminal needs no browser. An app that draws its own screen, like a game, puts a screenshot beside its boards and draws the change over it.
deploy design --helpdeploy help design prints the same. Plain text, like deploy --help
zsh
~/catan $ deploy design --help
deploy design — change what people see, and get it approved first

Usage  deploy design <command> [flags]

  start "<title>"          Start a design change on a branch from main
  propose                  Check it, push it and ask for review
  feedback                 Read the answer and the notes
  resolve <n> "<reply>"    Answer a note when it is done

While you draw
  dev                      Open the Design page on this folder, as you save
  check                    Draw what you changed beside main, once

Flags
  --project <name>         The project, when origin is elsewhere
  --wait                   feedback: stay until there is an answer
  --title, --summary, --look-at
                           propose: answer its questions up front
  --drop-instances         check: put carried boards back as on main
  --json                   Print the result as JSON
